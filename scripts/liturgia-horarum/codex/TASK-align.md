# 任务：圣咏中拉逐节对照（一批）

你会拿到一个输入文件（JSON 数组），每一项是一篇圣咏或颂歌（或其中一段）：拉丁文（新礼《时辰礼仪》2014 年标准版）和它的中文译本（香港教区礼仪委员会《每日颂祷》或“万有真原”）。网页要把它们按诗节并排显示，手机上一节拉丁文、紧接一节中文。自动对齐已经失败，现在由你按意思逐组配对。

## 输入的每一项

- `hash`：这一项的标识，输出时原样用作键。
- `key`：内部编号，仅供参考。
- `latin_heading`、`zh_heading`：标题部分，不需要配对。
- `latin_units`：拉丁正文，按顺序编号的单元。`kind: "line"` 是一行诗（`*` 为半节分隔，`†` 为转折，`[12]` 是节号）；`kind: "section"` 是分段标记（如 `II`）。
- `zh_body`：中文正文，各行以 `\n` 分隔。`※` 对应拉丁文的 `*`，`†` 对应 `†`；`壹`、`貳` 等是分段标记。

## 你要输出的

一个 JSON 对象，键是每一项的 `hash`，值是该项的分组列表：

```json
{
  "<hash>": [
    { "la": [0, 1], "zh": "请大家前来，向上主欢呼，\n向拯救我们的磐石歌舞。" },
    { "la": [2, 3], "zh": "……" }
  ]
}
```

- `la`：这一组包含的拉丁单元编号范围 `[起, 止]`（含两端）。各组按顺序、连续、不重叠地覆盖全部单元（从 0 到最后一个）。中文有、拉丁文完全没有对应的内容（极少见），用 `"la": null`。
- `zh`：这一组对应的中文，原文照抄。所有组的 `zh` 依次连起来（忽略空白和换行），必须与 `zh_body` 一字不差。

## 配对原则（最重要）

1. **每一组的中文必须正好是这一组拉丁文的译文。** 宁可把几节合成一组，也绝不能让某句中文落在与它意思不对应的拉丁文旁边。
2. 尽量细：一般一组就是一节诗（拉丁文的前半节 `*` 加后半节，通常一到三行）。
3. 可以零敲碎打地拆：中文某一行的后半句如果属于下一节拉丁文，可以在标点处把这一行切开，前半句留在本组，后半句放进下一组；同样，拉丁文的一两行如果在中文里并到了别处，就把相应拉丁行并进那一组。拆分只能发生在中文的标点处，或拉丁单元之间。
4. 中文调换了诗句顺序（例如把拉丁文后一节的意思放在前面）时，把涉及的几节合成一组，不要硬拆。
5. 分段标记：拉丁文 `section`（`II`）与中文 `貳` 一类的行，单独成一组配对；中文没有对应标记时，把它并入相邻一组。
6. 圣三光荣颂：拉丁文 `Gloria Patri …` 两行（或四行）与中文“愿光荣归于父……起初如何……”配成一组。
7. 不改动、增加、删除或调换任何一个中文字或标点。
8. 如果某一项的拉丁文和中文根本不是同一篇（比如编号不同、内容对不上），不要配对，输出 `"<hash>": {"skip": "原因"}`。

## 做法与检查

- 逐项阅读拉丁文和中文，按意思判断对应关系，不要只按行数或标记机械切分。
- 写完输出文件后，运行：`node check-align.mjs <输入文件> <输出文件>`，直到显示 `OK`。它只检查格式和原文是否一字不差，**意思是否对应要你自己保证**。
- 输出文件用 UTF-8 编码。
