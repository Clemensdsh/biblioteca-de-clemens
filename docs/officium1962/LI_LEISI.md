## 键与配对原则

- 键＝块内拉丁（去掉 `{ex Proprio Sanctorum}` 来源行）的字母哈希，**不是日期**。同一段拉丁出现在哪一天，译文都跟着出现（圣咏、共同礼对经、集祷经等）。旧礼规与 1962 不同的地方只会“没命中”，不会错位。
- 译本里同一块拉丁出现多处（如第一、第二晚祷的圣咏 109），都保留，页面优先显示与当前日期/时辰同源的一处；只有赞美诗这类各处同文的才并列「另一處同文」，专用版本（如带圣诞对经叠句的请经）不外借给别的日子。
- 圣咏后重复的对经（`Antiphona repetita`）不配译文。
- 配对是“按顺序贴到参考日期的拉丁块”（`build.mjs` 的 `alignSegment`），**每加一个段都要看 `--report` 逐条核对**，配错的用 `overrides.skip` 去掉。

## 加新章节

1. 在 `segments.json` 的 `segments` 里加段：`lines`（txt 行号范围）、`ref`（参考日期与时辰，必须是已发布 2026 年内的日期）、`repeatAfterPsalm`（译本在圣咏后是否重复对经；第一晚祷为 false）。
2. `node scripts/officium1962/li-leisi/build.mjs --report`，逐条核对拉丁与译文；未配到的单元要么加 `skip`，要么补段。
3. `pnpm officium1962:li-leisi`，再 `npx vitest run features/officium1962/liLeisi.test.ts`。

## 「云云」与「如前／見聖三」的处理（用户硬性要求：成品里不能有云云半成品，也不能因为写着「見聖三」就没有译文）

- **补全（`complete.mjs`）**：译本只载首句的单元，按书中他处补全，输出的段落带 `c:1`（页面标「據書中他處補全」）：
  1. `欽頌榮福云云` → 书中荣福经写法；括号里的礼仪提示（`(望全能仁慈天主云云)`）不是译文，去掉；
  2. 应答里 `P云云`（重复前面的半句）→ 同一单元里以 P 开头的整句或后半句；
  3. 整条只有首句（对经/圣咏/赞美诗/节目）→ **先**等配上拉丁块，若同一块拉丁在书中别处有全文就用全文（比按汉字首句查更可靠，如「主王已云云」可能是圣咏 92/96/98，由拉丁块决定）；没有再按首句到全书查（优先前文）；
  4. 祝文 `為…云云` → 同一篇祝文的全文，或书中「周年祝文」的结尾。
  `overrides.fill`（行→别行）、`overrides.fillText`（行→手写文字）用于书中笔误（如「牧童見誰」「宇宙請躍」）。
- **补不出的不输出**，`build.mjs --check` 把它们算作未完成：福音只引首句的（L1792、L1798、L1806，全书没有福音全文）、L2043 第 8 应答（「救世者云云」书中无对应全文）、L1920 圣咏 126「主非築城云云」（书中没有这篇圣咏全文）。
